Bend

a fast language that prevents AI mistakes via proofs

1.Bend compiles FAST.

When the AI writes the code, the compiler is the bottleneck. Proof assistants take minutes to check a mid-sized codebase. Bend checks that same code in one pass, in under one second.

2.Bend runs FAST.

On one core, Bend competes with hand-written C. And the same program, unchanged, runs on all sixteen cores, then the GPU: no threads, no locks, and not one GPU kernel written by you.

A call splits until each core holds a task; then the results fold back into one. Host and device share one memory, so not one byte is copied. The entire language compiles to kernels.

3.Bend blocks mistakes.

How can you trust code you never read? By demanding a proof. Take a game with a single law: the player can never win. You write that law in LAWS.bend, and Bend makes the AI prove it:

LAWS.bend

# LAW: no sequence of moves can ever lead to victory.
law winning_is_a_bug:
  for moves: List<Game.Move>
  board = Game.replay(Game.start(), moves)
  {Game.is_won(board) == False{} : Bool}

Now you prompt a new feature: "make the board wrap around".

Without LAWS.bend, the AI shipped a bug. With LAWS.bend, its code was rejected until it placed a wall and proved the law, for every possible sequence of moves. Not a test: a theorem.

LAWS.bend is AGENTS.md backed by proof. “Make no mistakes” becomes enforceable.

4.Get started.

4.1.Install

# needs Bun 1.3+ and clang; Metal or CUDA for the GPU
git clone https://github.com/HigherOrderCO/bend4
cd bend4
ln -s "$PWD/bend2/main.ts" ~/.bun/bin/bend

4.2.Save hello.bend

import Base

def main() -> IO(Unit):
  IO.print("Hello, world!")

4.3.Check, compile, run

bend hello.bend            # check + run
bend hello.bend -o hello   # native binary, GPU-enabled
./hello

Then read the guide. The core is formalized in Lean, and two papers describe it: BendTT, the type theory, and BendRT, the runtime. The compiler is young: expect bugs and report them.
